# 05 — Cost Allocation and Showback for GraphQL Platforms

> **Purpose**
> Per-team cost attribution, showback dashboards, chargeback models, cost efficiency metrics, budget alerting, and monthly cost review processes for a federated GraphQL platform. Enables platform teams to make infrastructure costs visible to subgraph teams, driving accountability and optimization. Written for platform engineering leads, engineering managers, and finance partners who need GraphQL cost visibility.

---

## Why Cost Allocation Matters for GraphQL Platforms

In a federated GraphQL platform, the platform team operates shared infrastructure (router, observability, service mesh) but the majority of compute and database cost is generated by individual subgraph teams. Without per-team attribution:

- Subgraph teams have no incentive to right-size their pods (they don't see the bill)
- Platform team cannot identify which team is driving the largest cost increase
- Budget planning is based on gut feel rather than data
- Cost optimization discussions lack specific, actionable targets

The goal of this document is to make the invisible visible: every team should know their monthly compute and database cost as clearly as they know their error rate.

## Per-Team Cost Attribution

### Namespace-Level Kubernetes Costs via Kubecost

Each subgraph team owns a dedicated Kubernetes namespace. Kubecost attributes costs at the namespace level, mapping CPU and memory consumption to dollar amounts.

```bash
# Kubecost API — monthly cost per subgraph namespace
KUBECOST_URL="https://kubecost.internal.example.com"

curl -s "${KUBECOST_URL}/model/allocation" \
  --data-urlencode "window=30d" \
  --data-urlencode "aggregate=namespace" \
  --data-urlencode "accumulate=true" \
  | jq '.data[] | select(.name | startswith("graphql-")) | {
    namespace: .name,
    cpuCost: (.cpuCost | . * 100 | round / 100),
    memoryCost: (.ramCost | . * 100 | round / 100),
    networkCost: (.networkCost | . * 100 | round / 100),
    totalCost: (.totalCost | . * 100 | round / 100)
  }'
```

Example output:

### Database Query Cost by Subgraph — pg_stat_user_tables

Database cost is typically 30–50% of total infrastructure cost for a GraphQL platform. Attribution requires mapping database query activity to subgraph teams:

```sql
-- Run on each PostgreSQL instance to get per-subgraph query volume
-- Each subgraph has its own database or schema, or uses application_name to identify itself

-- Option 1: per-database attribution (each subgraph has its own database)
SELECT
  datname AS database_name,
  sum(numbackends) AS current_connections,
  sum(xact_commit) AS commits_per_day,
  sum(tup_fetched) AS rows_fetched,
  sum(tup_inserted + tup_updated + tup_deleted) AS rows_written
FROM pg_stat_database
WHERE datname NOT IN ('postgres', 'template0', 'template1')
GROUP BY datname
ORDER BY rows_fetched DESC;

-- Option 2: application_name tracking (shared database, subgraph sets application_name)
-- In subgraph connection config:
-- connectionString: "postgresql://...?application_name=products-subgraph"

SELECT
  application_name AS subgraph,
  count(*) AS active_connections,
  sum(calls) AS total_queries,
  sum(total_exec_time) AS total_query_time_ms,
  avg(mean_exec_time) AS avg_query_time_ms
FROM pg_stat_statements
JOIN pg_stat_activity USING (query)
WHERE application_name LIKE '%subgraph%'
GROUP BY application_name
ORDER BY total_query_time_ms DESC;
```

**Convert query time to cost:**

```
PostgreSQL on RDS:
  db.r5.2xlarge: $0.504/hour = $362.88/month

  Total query time in last month: 50,000,000 seconds (across all subgraphs)
  Products subgraph: 20,000,000 seconds (40% of total)
  
  Products subgraph database cost attribution:
    40% × $362.88 = $145.15/month
```

## Chargeback Model

A chargeback model means the platform team invoices product teams for infrastructure consumption above a baseline allocation. This creates financial accountability for infrastructure decisions.

### Baseline Allocation Policy

```
Platform Team Policy (effective 2026-Q1):

Every subgraph team receives a free baseline allocation:
  Compute baseline: 2 CPU cores + 4GB RAM (always on)
  Database baseline: 1 read replica connection pool
  Observability: included in platform team budget

Usage above baseline is charged to the team's cost center at:
  CPU:    $0.07/vCPU-hour (blended on-demand + spot rate)
  Memory: $0.009/GB-hour
  
Monthly chargeback is calculated on the 1st business day of the following month.
Teams receive a 15-day window to dispute or flag anomalous charges.
```

### Chargeback Calculation Script

```python
#!/usr/bin/env python3
# scripts/chargeback.py — monthly chargeback calculator
import requests
from datetime import datetime, timedelta

KUBECOST_URL = "https://kubecost.internal.example.com"
BASELINE_CPU_CORES = 2.0
BASELINE_MEMORY_GB = 4.0
CPU_RATE = 0.07          # $/vCPU-hour
MEMORY_RATE = 0.009      # $/GB-hour

def get_namespace_costs(month_start: str, month_end: str) -> list:
    resp = requests.get(
        f"{KUBECOST_URL}/model/allocation",
        params={
            "window": f"{month_start},{month_end}",
            "aggregate": "namespace",
            "accumulate": "true",
        }
    )
    return resp.json()["data"]

def calculate_chargeback(namespace_data: dict) -> dict:
    namespace = namespace_data["name"]
    if not namespace.startswith("graphql-") or namespace == "graphql-platform":
        return None

    total_cpu_hours = namespace_data.get("cpuCoreHours", 0)
    total_memory_gb_hours = namespace_data.get("ramByteHours", 0) / (1024 ** 3)

    # Subtract baseline allocation
    hours_in_month = 720
    baseline_cpu_hours = BASELINE_CPU_CORES * hours_in_month
    baseline_memory_gb_hours = BASELINE_MEMORY_GB * hours_in_month

    billable_cpu_hours = max(0, total_cpu_hours - baseline_cpu_hours)
    billable_memory_gb_hours = max(0, total_memory_gb_hours - baseline_memory_gb_hours)

    cpu_charge = billable_cpu_hours * CPU_RATE
    memory_charge = billable_memory_gb_hours * MEMORY_RATE
    total_charge = cpu_charge + memory_charge

    return {
        "team": namespace.replace("graphql-", ""),
        "namespace": namespace,
        "total_cpu_hours": round(total_cpu_hours, 1),
        "baseline_cpu_hours": baseline_cpu_hours,
        "billable_cpu_hours": round(billable_cpu_hours, 1),
        "cpu_charge_usd": round(cpu_charge, 2),
        "memory_charge_usd": round(memory_charge, 2),
        "total_charge_usd": round(total_charge, 2),
    }

if __name__ == "__main__":
    today = datetime.now()
    last_month_start = (today.replace(day=1) - timedelta(days=1)).replace(day=1)
    last_month_end = today.replace(day=1) - timedelta(days=1)

    costs = get_namespace_costs(
        last_month_start.strftime("%Y-%m-%dT00:00:00Z"),
        last_month_end.strftime("%Y-%m-%dT23:59:59Z"),
    )

    chargebacks = [calculate_chargeback(ns) for ns in costs if calculate_chargeback(ns)]
    
    print(f"\nMonthly Chargeback Report — {last_month_start.strftime('%B %Y')}")
    print("=" * 70)
    for cb in sorted(chargebacks, key=lambda x: -x["total_charge_usd"]):
        print(f"Team: {cb['team']:<20} Total charge: ${cb['total_charge_usd']:>8.2f}")
        print(f"  CPU: {cb['billable_cpu_hours']:>6.1f} hours × ${CPU_RATE} = ${cb['cpu_charge_usd']:>7.2f}")
        print(f"  Memory: ${cb['memory_charge_usd']:>5.2f}")
    print("=" * 70)
    total = sum(cb["total_charge_usd"] for cb in chargebacks)
    print(f"Total platform chargeback: ${total:.2f}")
```

## Cost Efficiency Metrics

### Cost per Million GraphQL Operations

The primary efficiency metric — comparable across time periods and traffic levels:

```promql
# Cost per million operations (requires kubecost metrics in Prometheus)
# Numerator: total platform infrastructure cost per hour (in USD)
(
  sum(kubecost_namespace_cost_total{namespace=~"graphql-.*"})
  +
  sum(kubecost_namespace_cost_total{namespace="monitoring"})    # observability share
) * 720   # monthly cost
/
(
  sum(increase(apollo_router_graphql_requests_total[30d])) / 1000000
)
```

**Benchmarks:**

| Platform Maturity | Cost per Million Ops | Notes |
|------------------|---------------------|-------|
| Early-stage (< 1M ops/month) | $1.00–$5.00 | Fixed infrastructure cost dominates |
| Growing (10M–100M ops/month) | $0.20–$1.00 | Economy of scale improving |
| Mature (1B+ ops/month) | $0.05–$0.20 | Well-optimized; DataLoader and caching working |

### Cost per Active User

```promql
# Cost per monthly active user (MAU)
# Assumes user_id label is available in router metrics
(sum(kubecost_namespace_cost_total{namespace=~"graphql-.*"}) * 720)
/
sum(count_over_time(
  {__name__="apollo_router_graphql_requests_total"}[30d]
) by (user_id))
# Units: $/MAU/month
```

## Budget Alerts

### Kubernetes LimitRange and ResourceQuota Alerts

```yaml
# quota-alert-rules.yaml — alert when namespace approaches quota limit
groups:
  - name: graphql_budget_alerts
    rules:
      # Alert when a subgraph namespace is at 80% of its CPU quota
      - alert: GraphQLSubgraphApproachingCPUQuota
        expr: |
          (
            sum by (namespace) (kube_pod_container_resource_requests{resource="cpu", namespace=~"graphql-.*"})
            /
            sum by (namespace) (kube_resourcequota{resource="requests.cpu", namespace=~"graphql-.*", type="hard"})
          ) > 0.8
        for: 30m
        labels:
          severity: warning
          team: graphql-platform
        annotations:
          summary: "Namespace {{ $labels.namespace }} is at {{ $value | humanizePercentage }} of CPU quota"
          description: |
            The {{ $labels.namespace }} namespace is consuming {{ $value | humanizePercentage }} of its
            CPU quota. If this continues, pods may not be schedulable.
            Review team's HPA configuration and resource requests.
          runbook_url: "https://runbooks.internal.example.com/graphql/quota-exceeded"

      # Alert when monthly cost projection for a namespace exceeds budget
      - alert: GraphQLNamespaceOverBudget
        expr: |
          (kubecost_namespace_cost_total{namespace=~"graphql-.*"} * 720) > 500
        for: 24h
        labels:
          severity: warning
        annotations:
          summary: "{{ $labels.namespace }} projected monthly cost ${{ $value | humanize }} exceeds $500 budget"
          description: |
            Namespace {{ $labels.namespace }} monthly cost projection: ${{ $value | humanize }}.
            Budget threshold: $500/month.
            Review pod count, resource requests, and whether HPA maxReplicas is appropriate.
```

## Monthly Cost Review Process

### Automated Report Generation

```bash
#!/bin/bash
# scripts/monthly-cost-report.sh — run on the 1st of each month

REPORT_DATE=$(date -v-1m +"%B %Y")
OUTPUT="monthly-cost-report-$(date -v-1m +%Y-%m).md"

# GraphQL Platform Monthly Cost Report — $REPORT_DATE

Generated: $(date -u)

## Summary

| Namespace | CPU Cost | Memory Cost | Total Cost | MoM Change |
|-----------|---------|-------------|-----------|------------|

# Fetch kubecost data and append to report
python3 scripts/chargeback.py --format markdown >> $OUTPUT

cat >> $OUTPUT << EOF

## Cost Efficiency

- Cost per million operations: $(curl -s "https://prometheus..." | jq ....)
- Total platform operations this month: $(...)
- Active subgraph teams: $(kubectl get namespaces | grep graphql | wc -l)

## Top Optimization Opportunities

1. [Highest-cost team] — review HPA configuration and VPA recommendations
2. Observability cost: check trace sampling configuration

EOF

# Post to Slack #graphql-platform-ops
curl -s -X POST "$SLACK_WEBHOOK" \
  -H "Content-Type: application/json" \
  -d "{\"text\": \"Monthly cost report ready: $OUTPUT\nTotal: \$XXX | MoM change: +X%\"}"

echo "Report generated: $OUTPUT"
```

## PromQL Queries for Cost Metrics

```promql
# Total platform cost per hour (for trending)
sum(kubecost_namespace_cost_total{namespace=~"graphql-.*"})

# Cost breakdown: compute vs observability
sum(kubecost_namespace_cost_total{namespace=~"graphql-.*"})             # subgraph compute
+
sum(kubecost_namespace_cost_total{namespace="graphql-platform"})        # router + platform
+
sum(kubecost_namespace_cost_total{namespace="monitoring"}) * 0.3        # 30% of monitoring attributed to GraphQL

# Month-over-month cost change (requires 30d offset support)
(
  sum(kubecost_namespace_cost_total{namespace=~"graphql-.*"}) * 720
  -
  sum(kubecost_namespace_cost_total{namespace=~"graphql-.*"} offset 30d) * 720
)
/
sum(kubecost_namespace_cost_total{namespace=~"graphql-.*"} offset 30d) * 720

# Cost efficiency: $/million ops
(sum(kubecost_namespace_cost_total{namespace=~"graphql-.*"}) * 720 * 1000000)
/
sum(increase(apollo_router_graphql_requests_total[30d]))

# Team ranking by cost per operation (identifies most expensive-per-RPS subgraph)
sum by (namespace) (kubecost_namespace_cost_total{namespace=~"graphql-.*"})
/
sum by (subgraph_name) (rate(apollo_router_subgraph_requests_total[5m]))
```
